# 햇살마당 도서관 | 『열세 살의 덩크 슛』 독서 홈페이지

## 포함된 기능
- 첫 화면: 학년·반 및 이름만 입력 후 입장 (5학년 1~4반, 6학년 1~4반)
- 홈: 학급별 독서 미션 완료율·참여 학생 수·미션 진행 현황
- 학급별 독서 담벼락: 4가지 지정 구간 미션, 답변 등록, 다른 반 글 열람
- 작가 소개: YES24 소개 페이지 연결, 대표 도서 목록
- 작가에게 질문 및 새로운 책 아이디어를 제안하는 게시판
- 관리자 비밀번호 로그인, 학급 인원 변경, 전체 글/학생 현황, 글 삭제, CSV 내려받기
- 작가 전용 읽기 전용 URL (별도 토큰 설정 필요)
- Supabase PostgreSQL 데이터 영구 저장 (Render 서버 재시작에도 유지)

## 1. ZIP 압축 풀기
폴더 안에는 `server.js`, `package.json`, `public` 폴더 등이 있습니다.
**중요: 기존 7942 프로젝트에 덮어쓰지 마세요. 새 GitHub 저장소를 사용하세요.**

## 2. GitHub 새 저장소 만들기
1. github.com 로그인 후 오른쪽 위 `+` → `New repository` 선택
2. 예: 저장소 이름 `haetsal-book-reading`으로 만들기 (Private 가능)
3. `Add file` → `Upload files`를 눌러 **압축을 푼 폴더의 내용물**(server.js, package.json, public 등)을 올립니다.
4. `.env` 파일이나 실제 비밀번호는 절대 GitHub에 올리지 마세요. `.env.example`은 견본 파일입니다.

## 3. Supabase 데이터베이스
1. supabase.com에서 새로운 프로젝트 생성 (기존 7942 DB와 별도 프로젝트 권장)
2. 프로젝트 생성 후 `Connect`에서 **Session pooler** PostgreSQL 연결 문자열을 복사합니다.
3. 복사한 문자열의 `[YOUR-PASSWORD]` 등을 **이 새 프로젝트의 DB 비밀번호**로 교체합니다.
4. 따로 SQL을 실행할 필요는 없습니다. 서버가 처음 시작될 때 필요한 테이블 4개를 자동 생성합니다.
5. 연결 문자열과 DB 비밀번호는 개인 메시지·공개 GitHub·사이트 게시판에 공개하지 마세요.

## 4. Render 무료 Web Service 만들기
1. render.com 로그인 → `New +` → `Web Service`
2. 새 GitHub 저장소를 연결해 선택
3. Runtime: **Node**, Branch: main, Root Directory: 비워두기(폴더 내용물을 루트에 업로드한 경우)
4. Build Command: `npm install`
5. Start Command: `npm start`
6. 요금제 선택 시 Free가 가능하면 Free 선택
7. `Environment`에 아래 변수를 추가합니다.

| Key | Value |
| --- | --- |
| `DATABASE_URL` | Supabase에서 복사한 **Session pooler 연결 문자열** |
| `ADMIN_PASSWORD` | 12자 이상 복잡한 관리자 암호 |
| `SESSION_SECRET` | 32자 이상 무작위 문자열 (관리자 세션 서명 키) |
| `AUTHOR_TOKEN` | 32자 이상 별도의 무작위 문자열 (작가용 읽기 전용 링크 키) |
| `NODE_ENV` | `production` |

8. `Deploy Web Service` 클릭 → Logs에서 실행에 성공했는지 확인
9. 발급된 `https://...onrender.com` 주소를 열어 학생 로그인 화면 확인

**중요:** `ADMIN_PASSWORD`, `SESSION_SECRET`, `AUTHOR_TOKEN`은 서로 다른 값을 사용하세요. 기존 프로그램 비밀번호나 DB 연결 문자열을 재활용하지 마세요.

## 5. 관리자 설정
1. 홈페이지 맨 아래 `관리자` 클릭
2. Render에 등록한 `ADMIN_PASSWORD` 입력
3. 학급별 `전체 학생 수`를 입력하고 각각 `인원 저장` 클릭
4. 테스트용 학생 이름으로 미션을 하나 등록해 본 뒤, 관리자에서 답변 확인 및 삭제 테스트
5. 각 학급의 완료율/참여율은 자동 계산됩니다.

**완료율 공식:** `중복을 제외한 학생별 미션 완료 개수 ÷ (학급 전체 학생 수 × 4) × 100`
**참여율 공식:** `미션을 한 번 이상 작성한 학생 수 ÷ 학급 전체 학생 수 × 100`
같은 학생이 미션 하나에 글을 여러 번 올려도 완료 횟수는 1개입니다.

## 6. 작가님께 주소 전달
작가님에게 아래 형식의 **읽기 전용** 링크만 전달하세요.

`https://내-사이트.onrender.com/?author=AUTHOR_TOKEN_값`

관리자 암호나 데이터베이스 연결 문자열은 절대로 전달하지 마세요.
작가용 링크를 가진 사람은 게시물을 볼 수 있습니다. 전달 대상을 제한하고 행사가 끝나면 `AUTHOR_TOKEN`을 변경하면 기존 링크를 폐기할 수 있습니다.

## 7. 운영 시 주의할 점
- 학생은 학년·반과 이름만 입력하므로 **실제 본인 확인 기능은 없습니다**. 다른 학생의 이름으로 글을 올리는 행위를 기술적으로 완전히 막을 수 없습니다.
- **동명이인**이 같은 반에 있다면 하나의 학생으로 집계될 수 있습니다. 이 경우 별도 식별코드를 추가하거나 학생 명단 기반 로그인으로 바꿔야 합니다.
- 일반 학생·작가에게는 이름을 일부 가려서 보여주고, 관리자에게는 전체 이름이 보입니다.
- 실명과 독서 답변은 개인정보에 해당할 수 있으므로 학교의 개인정보 처리 지침에 따라 이용 안내·접근 제한·보유기간·삭제를 결정하세요. 현재 버전은 작성된 게시물이 곧바로 공개되는 방식입니다. **사전 승인형 검수 기능은 포함되지 않았습니다.**
- 행사 후에는 관리자에서 CSV로 필요한 자료를 내려받고 개인정보 보유기간에 맞춰 기록을 정리하세요.
- Render 무료 서비스는 사용하지 않으면 잠들었다가 첫 접속 때 수십 초 걸릴 수 있습니다. 무료 요금제와 Supabase 프로젝트의 제약은 각 업체 화면에서 확인하세요.
- 로컬 PC에서 시험할 때 `DATABASE_URL`이 없으면 `local-data.json`에 저장합니다. **이 방식은 데모 전용**이며 Render 운영 시 반드시 Supabase를 연결해야 합니다.
- 학급별 인원 수를 학생 수보다 작게 설정하면 완료율이 100%에서 멈출 수 있으므로 정확히 입력하세요.

## 8. 내용 수정 방법
- 미션 페이지·질문: `public/app.js`의 맨 위 `missionInfo`
- 디자인 색상·배치: `public/styles.css`

- 학교/행사 정보: `public/app.js`

## 9. 문제 해결
- Render 오류 `필수 환경변수 ... 누락`: Environment에 3개 이상의 필수 키 입력
- DB 오류: Supabase Connect > Session pooler 연결 문자열, 비밀번호, 프로젝트 상태 확인
- 학생 게시물이 사라짐: Environment에서 `DATABASE_URL`이 올바르게 설정됐는지 확인. `/api/health`에서 `storage: postgres`여야 합니다.
- 관리자 로그인 실패: Render `ADMIN_PASSWORD` 값 확인, 업데이트 후 재배포
- 홈페이지 수정이 반영되지 않음: GitHub에 변경 저장 → Render 배포 완료 → 브라우저 새로고침
